# 001. 데이터 분석 및 전처리

**프로젝트:** 공유자전거 대여 수요 예측 (회귀)  
**작성 범위:** CP-01~CP-03  
**근거:** `01_regression_bike_demand.ipynb`의 코드와 실행 결과

## 1. 데이터 탐색 (CP-01)

- **데이터 크기:** 17,379행, 17열. 한 행은 특정 날짜와 시간대의 대여 기록이며, `cnt`는 해당 시간의 총 대여량이다.
- **결측값 및 중복 행:** 모든 컬럼의 결측값은 0개이고, 모든 컬럼이 같은 중복 행도 0개다.
- **대여량 분포:** 시간당 평균은 약 189.5대, 중앙값은 142대이며 최솟값은 1대, 최댓값은 977대다. 낮은 대여량 구간에 기록이 많이 모이고 큰 값 쪽으로 꼬리가 길다.
- **시간대별 평균:** 8시 약 359대, 17시 약 461대, 18시 약 426대로 높았고, 4시는 약 6대로 가장 낮았다.

**분석:** 대여량이 시간대에 따라 달랐으며 출퇴근 시간과 관련이 있을 가능성이 있다. 다만 이는 전체 기간의 시간대별 평균이므로, 출퇴근 수요의 영향은 근무일과 휴일을 나누어 추가로 확인해야 한다.

## 2. 데이터 분할 및 누수 확인 (CP-02)

| 구분 | 날짜 | 행 수 |
| --- | --- | ---: |
| Train | 2011-01-01 ~ 2012-05-25 | 12,139 |
| Validation | 2012-05-26 ~ 2012-09-11 | 2,616 |
| Test | 2012-09-12 ~ 2012-12-31 | 2,624 |

- **분할 기준:** 날짜를 시간순으로 정렬해 약 70:15:15로 나눴으며, 같은 날짜의 기록은 한 집합에만 둔다. 과거로 학습하고 이후 기간을 예측하는 상황을 재현하기 위해서다.
- **대여량 관계 확인:** `casual + registered == cnt`는 모든 행에서 `True`였다.
- **누수 방지:** `casual`과 `registered`는 정답 `cnt`의 구성 요소이며 예측 시점에 알 수 없으므로 입력에서 제외했다. `cnt`는 정답으로 분리하고, 행 식별자인 `instant`와 날짜 분할에 사용한 `dteday`도 입력에서 제외했다.

**분석:** 각 집합은 서로 다른 시기에 해당하므로 계절과 수요 패턴의 차이가 모델 성능에 영향을 줄 수 있다. 실습 파일의 분할 결과에는 집합별 `cnt` 평균이 출력되어 있지 않다. 분할된 데이터에서 별도로 계산하면 기간별 수요 수준을 정량적으로 비교할 수 있다.

## 3. 상관관계 및 입력 특성 분석 (CP-02)

Train 데이터에서 계산한 피어슨 상관계수는 다음과 같다.

| 특성 쌍 | 상관계수 |
| --- | ---: |
| 기온 `temp`와 대여량 `cnt` | 0.398 |
| 체감온도 `atemp`와 대여량 `cnt` | 0.398 |
| 습도 `hum`와 대여량 `cnt` | -0.301 |
| 풍속 `windspeed`와 대여량 `cnt` | 0.094 |
| 기온 `temp`와 체감온도 `atemp` | 0.992 |

- **기본 입력 특성 12개:** `season`, `yr`, `mnth`, `hr`, `holiday`, `weekday`, `workingday`, `weathersit`, `temp`, `atemp`, `hum`, `windspeed`.
- **예측 시점 가정:** 시간, 달력 정보와 날씨 정보를 사용하며, 미래 날씨는 예보로 얻을 수 있다고 가정했다. 다만 실습에서는 실제 예보 오차가 성능에 미치는 영향을 평가하지 않았다.

**분석:** 기온과 대여량은 양의 선형 관계, 습도와 대여량은 음의 선형 관계를 보였고 풍속의 선형 관계는 약했다. 기온과 체감온도는 서로 매우 비슷하게 움직였지만, 상관계수 하나만으로 특성을 제외할 수는 없다. 실제 도움이 되는지는 모델을 다시 학습하고 검증 성능을 비교해야 한다.

## 4. 특성공학 및 전처리 (CP-03)

- **생성한 특성:** `is_commute_hour`. 근무일(`workingday=1`)이면서 시간이 7, 8, 9시 또는 17, 18, 19시면 1, 그 외에는 0이다.
- **범주형 5개:** `season`, `mnth`, `hr`, `weekday`, `weathersit`을 원-핫 인코딩했다. Train에 없던 범주는 `handle_unknown="ignore"`로 처리한다.
- **수치형 4개:** `temp`, `atemp`, `hum`, `windspeed`를 표준화했다.
- **이진형 4개:** `yr`, `holiday`, `workingday`, `is_commute_hour`는 그대로 전달했다.
- **전처리 전후 Shape:** Train `(12139, 13)` → `(12139, 59)`, Validation `(2616, 13)` → `(2616, 59)`. 범주형 열이 여러 0/1 열로 나뉘어 열 수가 늘었다.
- **Validation 변환 기준:** 범주 목록과 표준화 기준은 Train에서 학습하고 Validation에는 같은 기준을 적용했다.

**추가 실험과 최종 입력:** 출퇴근 특성을 포함한 전처리 결과는 위와 같다. 이후 CP-07에서 같은 랜덤 포레스트 설정으로 출퇴근 특성만 제외해 재학습하자 Validation MAE가 94.532대에서 86.194대로 낮아져, 최종 모델에는 이 특성을 제외했다. 이는 이번 검증 기간에서의 비교 결과다.

## 5. 데이터 분석 요약

- 과거와 미래를 구분해 분할하고, 정답을 구성하는 `casual`과 `registered`를 입력에서 제외해 데이터 누수를 방지했다.
- 시간대별 대여량 차이가 컸으며, 새로 만든 출퇴근 특성의 유용성은 실제 검증 실험으로 확인했다. Train과 Validation이 서로 다른 기간이므로 성능 차이를 해석할 때 계절과 수요 변화도 고려한다.
