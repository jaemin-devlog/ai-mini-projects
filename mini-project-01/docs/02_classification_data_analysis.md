# 003. 데이터 분석 및 전처리

**프로젝트:** 온라인 쇼핑 구매 여부 예측 (PyTorch 신경망 분류)
**작성 범위:** CP-01~CP-03
**근거:** `code/02_classification_online_shopping.ipynb`의 코드와 실행 결과

## 1. 데이터 탐색 및 클래스 분포 (CP-01)

방문자의 행동으로 구매 여부를 예측하기 전에 데이터가 어떤 형태인지 확인했다. 한 행이 무엇을 나타내는지, 비어 있는 값이나 같은 행이 있는지, 구매와 미구매가 얼마나 되는지 살펴봤다.

- **데이터 크기:** 12,330행, 18열. 한 행은 쇼핑몰 방문 세션 하나다.
- **결측값 및 중복 행:** 결측값은 0개, 모든 열의 값이 같은 중복 행은 125개다. 서로 다른 세션이 같은 특성값을 가질 수 있고 동일 기록이라는 근거가 없어 삭제하지 않았다.
- **수치형 특성:** 상품 페이지 방문 횟수, 체류시간, 페이지 가치는 작은 값에 세션이 몰려 있고 일부 큰 값 쪽으로 길게 분포한다. 종료율은 낮은 값에 많이 몰려 있으며 0.20 부근에도 세션이 있다.
- **구매 (`Revenue=1`):** 1,908건, 15.47%.
- **미구매 (`Revenue=0`):** 10,422건, 84.53%.

**분석:** 구매한 방문이 전체의 15.47%여서 모델이 미구매만 예측해도 정확도가 약 84.53%가 된다. 이 경우 실제 구매는 하나도 찾지 못한다. 모델을 비교할 때 정확도 외에 구매를 얼마나 정확하게 예측했는지와 실제 구매를 얼마나 찾았는지도 확인하기로 했다.

## 2. 계층화 데이터 분할 (CP-02)

| 집합 | 세션 수 | 구매 비율 |
| --- | ---: | ---: |
| Train | 8,630 | 15.48% |
| Validation | 1,850 | 15.46% |
| Test | 1,850 | 15.46% |

- **분할 방법:** 구매가 적은 데이터이므로 각 집합의 구매 비율이 크게 달라지지 않도록 `stratify`를 두 번 사용해 약 70:15:15로 나눴다. Test 15%를 먼저 분리한 뒤 남은 85%에서 `0.15 / 0.85` 비율을 Validation으로 나눴다.
- **회귀와의 차이:** 회귀 프로젝트는 과거에서 미래를 예측하는 상황을 반영해 날짜순으로 나눴다. 이번에는 클래스 불균형을 고려해 구매 비율을 유지하면서 세션을 무작위 분할했다.

- **중복 확인:** Train과 Validation 양쪽에 같은 값의 행 29종류가 있었다. Train + Validation과 Test 사이에는 같은 값의 행 15종류가 있었고 Test 20행이 해당했다. 동일한 값이 반드시 같은 방문을 뜻하지는 않는다.

**분석:** 세 집합의 구매 비율은 모두 약 15.5%다. 무작위 분할은 미래 기간이나 동일 고객의 반복 방문을 분리한 평가가 아니다. 같은 값의 행이 집합 간에 있어 결과를 해석할 때 고려한다.

## 3. 구매 여부와 관련된 특성 분석 (CP-02)

방문 유형과 행동에 따라 구매 양상이 다른지 살펴봤다. 특성 분석에 쓴 결과는 Train에서만 계산했다.

| 방문자 유형 | 세션 수 | 구매율 |
| --- | ---: | ---: |
| New_Visitor | 1,162 | 25.22% |
| Other | 63 | 15.87% |
| Returning_Visitor | 7,405 | 13.95% |

신규 방문의 구매율이 가장 높았고 재방문 세션이 가장 많았다. Other는 63건으로 적어 비율이 소수의 구매 건수에 민감하다.

| 특성 | 미구매 중앙값 | 구매 중앙값 |
| --- | ---: | ---: |
| `ProductRelated` | 16 | 29 |
| `ProductRelated_Duration` | 517.580초 | 1,069.658초 |
| `PageValues` | 0.000 | 17.543 |
| `ExitRates` | 0.029 | 0.015 |

**분석:** 구매 그룹의 상품 관련 페이지 방문 횟수와 체류시간 중앙값이 더 높았다. 그룹 간 관찰 차이이므로 구매의 원인이라고 단정할 수 없다. `PageValues`는 구매 등 목표 달성과 관련된 값으로, 방문 초기의 실시간 예측에 사용할 수 있는지는 별도 확인해야 한다. 특성 분석은 Train에서 수행했으며, Validation은 모델 비교에 사용했다.

## 4. 데이터 전처리 및 PyTorch 입력 준비 (CP-03)

모델이 방문 유형이나 브라우저 번호를 숫자의 크기로 해석하지 않도록 범주형 입력을 나눴다. 페이지 수와 체류시간처럼 크기 범위가 다른 수치형 입력은 표준화했다. 검증 데이터의 정보가 학습 기준에 섞이지 않도록 전처리는 Train으로 학습했다.

- **범주형 6개:** `Month`, `OperatingSystems`, `Browser`, `Region`, `TrafficType`, `VisitorType`을 One-Hot 인코딩했다. 숫자로 표시된 운영체제와 브라우저 등도 크기가 아닌 종류를 나타내므로 범주형으로 처리했다.
- **수치형 10개:** `Administrative`, `Administrative_Duration`, `Informational`, `Informational_Duration`, `ProductRelated`, `ProductRelated_Duration`, `BounceRates`, `ExitRates`, `PageValues`, `SpecialDay`를 표준화했다.
- **이진형:** `Weekend`는 0/1 값을 그대로 전달했다.
- **변환 기준:** 범주 목록과 표준화 기준은 Train에서 학습하고 Validation에는 동일한 기준을 적용했다. Train에 없는 범주는 `handle_unknown="ignore"`로 처리한다.
- **입력 Shape:** Train `(8630, 17)` → `(8630, 73)`, Validation `(1850, 73)`으로 변환됐다.
- **Tensor:** 입력과 정답을 `torch.float32`로 변환했다. Train 입력은 `(8630, 73)`, 정답은 `(8630,)`이다.
- **DataLoader:** 배치 크기 256, 총 34개 미니배치이며 마지막 배치는 182건이다. 학습 데이터 순서는 섞고 시드 42를 사용한다.

**분석:** PyTorch에서 연산할 수 있도록 Tensor로 변환하고, 데이터를 여러 미니배치로 나눠 학습할 준비를 했다. 원-핫 인코딩으로 범주형 열이 펼쳐져 입력 열 수가 늘었다.

## 5. 데이터 분석 요약

- 구매는 전체의 15.47%로 적어 정확도만으로 구매 예측 성능을 판단하기 어렵다.
- Train에서 학습한 전처리를 Validation에 적용했다. `PageValues`를 포함한 입력이 방문 초기에 모두 이용 가능하다고 가정하지 않는다.
