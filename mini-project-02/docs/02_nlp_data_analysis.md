# 003. 데이터 분석 및 초기 가설

**프로젝트:** BERT 기반 한국어 의미 검색 시스템 개발 및 성능 비교 (NLP)  
**작성 범위:** CP-01

> Notebook의 CP-01 실행 결과를 바탕으로 작성했다. 초기 가설은 CP-01에서 기록한 내용을 유지했다.

## 1. 검색 데이터셋 구조 (CP-01)

- **데이터 출처:** KLUE-MRC의 Validation 데이터에서 재구성한 교육용 검색 데이터
- **Corpus:** 200개 문단
- **Validation / 보류 Test:** 질문 60개 / 20개
- **질문과 정답 문서의 연결 기준(`relevant_doc_id`):** 원본 문단에서 답이 포함된 부분을 추출하고, 해당 문단의 `doc_id`를 정답으로 연결한다. 질문마다 지정된 정답 문단은 1개이다.
- **Validation과 Test가 동일한 Corpus를 사용하는 의미:** 같은 문단 200개에서 서로 다른 질문의 검색 성능을 평가한다. Test는 새로운 질문에 대한 성능을 확인하는 용도이며, 새로운 문서 집합에 대한 성능은 따로 확인해야 한다.

> 아래 분석에서는 Corpus와 Validation 질문만 사용한다. 보류 Test 질문은 CP-10에서 평가한다.

## 2. 문서·질문 길이 분석 (CP-01)

`corpus_stats['char_length']`와 `valid_stats['char_length']`의 통계와 히스토그램을 확인했다. 단위는 글자 수이다.

| 구분 | 평균 | 중앙값 | 최소 | 최대 |
|---|---:|---:|---:|---:|
| Corpus 문서 | 499.66 | 500 | 498 | 500 |
| Validation 질문 | 29.22 | 28 | 13 | 54 |

**분석:** 문서는 498~500자에 몰려 있고 질문은 13~54자에 걸쳐 있다. 짧은 질문으로 긴 문단에서 관련 내용을 찾아야 한다. BERT의 입력 제한으로 문단 일부가 잘리면 필요한 정보가 빠질 수 있다. 실제로 잘리는지는 토큰 수를 확인해야 한다.

## 3. 질문–정답 문단의 문자 겹침 비율 (CP-01)

`valid_overlap`은 질문의 어절 안에서 만든 고유한 두 글자 묶음 중 정답 문단에도 나오는 비율이다. TF-IDF 유사도 점수와는 계산 방식이 다르다.

- **Validation 전체 겹침 비율의 평균 / 중앙값:** 0.474 / 0.462
- **겹침 비율의 최소 / 최대:** 0.158 / 0.882
- **겹침 비율이 낮은 대표 질문 1개(ID / 질문 / 겹침 비율):** QV018 / 소위 천의 여왕으로 불리는 인물이 대륙에 발표한 방책은 무엇인가? / 0.158
- **해당 정답 문단에서 확인한 표현 차이:** 정답 문단 `D157`에서는 질문의 "방책"을 "마법금지정책", "대륙에 발표한"을 "대륙 전체에 ... 공표하게 된다"로 표현한다. 질문의 "천의 여왕"도 문단에서는 "천(天)의 여왕"으로 적혀 있다.

**분석:** 평균과 중앙값은 비슷하지만 최솟값과 최댓값의 차이가 크다. 질문마다 문자 겹침 정도가 다르며, 겹침이 낮으면 공통 문자 묶음이 적어 TF-IDF가 정답 문단을 찾기 어려울 수 있다.

> 참고 결과: `outputs/tables/cp01_validation_overlap.csv`

## 4. 검색 성능에 대한 초기 가설 (CP-01)

- **가설 ① TF-IDF가 유리할 것으로 예상하는 질문 유형과 이유:** 질문과 정답 문단에 같은 문자 묶음이 많으면 잘 찾을 것으로 예상한다. TF-IDF가 공통 문자 묶음을 바탕으로 유사도를 계산하기 때문이다.
- **가설 ② BERT 기반 검색이 유리하거나 불리할 것으로 예상하는 질문 유형과 이유:** 표현이 달라도 의미가 비슷하면 잘 찾을 것으로 예상한다. 다만 비슷한 문단이 많거나 중요한 내용이 입력 길이 제한으로 잘리면 찾기 어려울 수 있다.
